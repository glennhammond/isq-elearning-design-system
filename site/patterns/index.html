Learning patterns

What pattern should I use for this learning need?

Patterns are platform-neutral. Each can have more than one component or platform implementation, but its learning purpose stays stable. Do not create a new component before checking whether an existing pattern and variant can serve the need.

Section opener

Purpose: Orient the learner at a genuine structural transition.

Use when

A major section genuinely begins — not every subtopic.

Avoid when

Used for every heading change, which flattens its meaning.

Rise: native banner or the approved custom section opener.

Explanation

Purpose: Introduce and explain a concept with clear hierarchy and readable density.

Use when

Building core knowledge the learner needs before acting on it.

Avoid when

The content is really a single retainable point — use Key message instead.

Rise: native image-and-text is preferred; split card only where the image adds real meaning.

Split card → Panel →

Key message

Purpose: Isolate the one point a learner should retain.

Use when

One legal threshold, definition or critical reminder.

Avoid when

Routine supporting detail, or more than one message in a single panel.

One to three sentences. Use ordinary body text with a subheading as the fallback.

Key message →

Legislation or authority

Purpose: Separate source requirements from plain-English interpretation.

Use when

A specific Act, regulation or section underpins a requirement.

Avoid when

A general policy statement with no legislative source — use a standard content panel.

Always name the instrument precisely and keep the plain-English summary visibly separate from the quoted source.

Scenario stage

Purpose: Present new context or evidence from the decision-maker's perspective.

Use when

A discrete context, update, observation or piece of evidence within a running scenario.

Avoid when

General explanation unrelated to the scenario — use a split card or standard panel.

Keep one stable visual environment and decision-maker perspective across a whole scenario.

Scenario stage →

Decision point

Purpose: Require a realistic professional judgement and reveal the reasoning behind it.

Use when

A genuine professional juncture with credible distractors and consequential feedback.

Avoid when

An obvious answer with implausible distractors — use a native knowledge check for simple recall instead.

Feedback must explain why an option is appropriate, not only whether it was selected.

Decision point →

Feedback

Purpose: Explain why a choice is appropriate, not only whether it is correct.

Use when

Immediately after every decision, revealed in place.

Avoid when

As a generic correct/incorrect message with no reasoning.

Announce revealed feedback appropriately; place it immediately after the action that caused it.

Decision point →

Process

Purpose: Present actions or stages in a meaningful, genuinely ordered sequence.

Use when

Order is real and matters to the outcome.

Avoid when

The steps are not truly sequential — a card grid or list communicates it more honestly.

Use numbering only where the number carries meaning.

Process block →

Comparison

Purpose: Clarify differences between roles, responses or alternatives.

Use when

Two related audiences or positions need to be held side by side, with parallel categories.

Avoid when

More than a handful of items — use a card grid or table instead.

Keep categories parallel and the differences explicit; this is the pattern behind the shared Role split component — course-specific one-off comparisons (see Governance) should be migrated to it.

Role split →

Reflection

Purpose: Prompt considered application without adding unnecessary interaction.

Use when

A short self-assessment or reflective prompt genuinely aids transfer.

Avoid when

As a large, decorative treatment — the legacy Editorial reflection component exists only for backwards compatibility.

Prefer native statement/reflection blocks or a compact approved panel; use the self-assessment table only where a structured rating genuinely helps.

Self-assessment →

Resource

Purpose: Explain what a linked item is, why it matters and what will happen when it opens.

Use when

A supplementary document or external guidance needs context before the click.

Avoid when

Essential learning is available only through the external link — bring it into the course itself.

Name the resource and why it matters; a native attachment or text link is the fallback for lighter cases.

Resource card →

Section summary

Purpose: Close a major section and reinforce the intended learning.

Use when

The end of a major section, before a genuine transition.

Avoid when

After every subtopic.

Three to five concise points; the dark/footer band gives it a deliberate structural close.
